# Base Training Language Evaluation (Phase 11)

Phase 10 measures whether *training itself* behaved correctly (loss
finiteness, checkpoint integrity, throughput). Phase 11's language
evaluation measures something Phase 10 does not: whether the resulting
checkpoint produces a lower loss on held-out text in each language the
project cares about.

## Fixed evaluation fixtures

`core_model/training/fixed_eval_fixtures.py` defines a versioned
(`FIXTURE_VERSION = "phase11-fixed-eval-v1"`), hand-composed set of Tamil,
English, Tanglish, and mixed-script sentences. These sentences:

- are never sourced from any training dataset,
- are never generated by any Brud AI model,
- are never regenerated per run — the same fixture set is reused across
  every experiment so results are comparable over time.

Every language-metric evaluation extends the dataset's own validation/test
records for that language with the fixed fixture sentences for that
language, so a language with very few dataset records (a real risk given
[[base_training_dataset_profile]]'s `limited_experiment` status) still gets
a non-empty, independent evaluation set.

## What is measured

`core_model.training.language_evaluation.evaluate_language_texts()` encodes
each text independently (never batching across texts, so one long text
cannot skew another's loss), truncates to `min(model_config.context_length,
BRUD_PRETRAINING_MAX_SEQUENCE_LENGTH)` (counted in `long_sequence_rate`
rather than silently dropped), and returns per-language: evaluated record
and token counts, loss, perplexity (`core_model.training.diagnostics.
safe_perplexity`, which returns `None`/`inf`-safe values instead of
crashing on a bad loss), unknown-token rate, and sequence-length statistics.

## Splits

- `valid` — computed on every `POST /runs/{id}/evaluate` call.
- `test` — computed at most once per run (`base_training_experiment_runs.
  test_evaluated`), and only ever as part of candidate selection
  (`select_candidate()` calls the same evaluation with `include_test=True`).
  This prevents the held-out test split from being used for iterative
  tuning, which would silently turn it into a second validation set.

Metrics for `ta`, `en`, `tgl`, `mixed`, and `overall` are persisted as
separate append-only rows in `base_training_language_metrics`
([[database_schema_v11]]) — `overall` is the same computation over the
union of all four language buckets, not a separate sampling pass.

## Known limitation

If the experiment's dataset is `limited_experiment` (below the 500-record
minimum), per-language record counts may be very small, and the fixed
fixture sentences make up most or all of a given language's evaluated set.
This is reported explicitly (see [[base_training_reproducibility]]'s
`known_limitations`), not hidden behind an otherwise-normal-looking metric.
