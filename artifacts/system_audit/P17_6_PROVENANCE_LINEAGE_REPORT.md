# Phase 17.6 — Provenance & Lineage Report
**Brud Mini Brain: Lineage Graph, Evidence Aggregation & Reversibility**

## 1. Provenance Preservation Requirements
Every canonical record generated by Phase 17.6 must be 100% traceable back to its root observations.

### Lineage Graph Representation:
```
[Observation 1: ID-101] (Turn 4, Session A) ──┐
[Observation 2: ID-102] (Turn 9, Session A) ──┼──► [Canonical Knowledge: ID-901]
[Observation 3: ID-103] (Turn 2, Session B) ──┘    • source_references: [ID-101, ID-102, ID-103]
                                                   • evidence_count: 3
                                                   • compression_method: deterministic_structural
```

## 3. Reversibility and Reconstruction Workflow
Because source memory records are transitioned to status `consolidated` (rather than being dropped or hard-deleted):
1. **Evidence Lookup**: Querying `get_versions()` or a dedicated `get_consolidated_sources(canonical_public_id)` returns all constituent items with their original display values, turn IDs, and sessions.
2. **Rollback (`unconsolidate_memory`)**:
   - The canonical record is updated to `status = 'superseded'` or `status = 'revoked'`.
   - The constituent records are restored to `status = 'active'`.
   - An immutable `UNCONSOLIDATED` event is appended to `memory_item_events` with admin provenance.
