## Summary counts

- `WORKING` (fully, in its own real scope): 13 rows.
- `ADMIN_ONLY` (working, but not publicly reachable): counted within the
  `WORKING` rows above — 11 of the 13 `WORKING` rows are additionally
  `ADMIN_ONLY`.
- `PARTIAL`: 8 rows.
- `MISSING`: 13 rows.
- `PRESENT_NOT_WIRED` / `TEST_ONLY` / `BLOCKED` / `DEPRECATED`: 0 rows
  each — no capability in this matrix fits those specific labels once
  investigated (the closest candidates, e.g. the safety taxonomy, were
  classified `TEST_ONLY` for the taxonomy specifically and `MISSING` for
  live enforcement, kept as two separate facts rather than one blended
  label).
- `NOT_APPLICABLE`: 1 row (alternate model-inference providers — the
  project correctly has none and needs none).

**The dominant pattern across this whole matrix**: most "MISSING" rows
are genuinely new subsystems that must be built from scratch (safety
live-enforcement, web search, MCP, translation, freshness/domain/intent
classification, knowledge-gap registry). Most "PARTIAL"/"ADMIN_ONLY"
rows are **already-working systems that need a public integration layer
and, in a few cases, a default-policy change (Tanglish output) — not a
rebuild.** This distinction is the load-bearing conclusion for the
Phase 17-26 ordering.
